### 1. Playmogo Mega Upload Corruption — Root Cause & Fix

All `pmvdl_*` files uploaded to Mega were corrupted with "Invalid key/Decryption error". Investigation confirmed 3 separate files all failed identically.

**Root cause**: `mega-exec put -q` (async queue flag). MEGAcmd creates the Mega file node immediately but uploads data asynchronously. A false-positive `mega-exec ls` check triggered Swift's `defer { removeItem(at: tempFile) }` while MEGAcmd was still reading the file. MEGAcmd read a deleted/partial file → AES-128-CTR metadata corrupted → permanent decryption error, unrecoverable.

**Fixes in `MegaManager.swift`**:
- Removed `-q` flag from `mega-exec put` — now synchronous, blocks until upload done
- `defer` cleanup only runs after `q.waitUntilExit()` — race condition eliminated
- Fixed `pathExtension` returning `""` (not nil) for cloudatacdn.com URLs — fallback to `"mp4"` now triggers correctly
- Added HTTP status + HTML magic-byte validation in `didFinishDownloadingTo` to reject CDN error pages before writing to disk

**Fixes in `DoodStreamExtractor.swift`**:
- Set `mp4: nil` for Playmogo — URL only exposed via `hls` quality entry with required `Referer` headers
- Prevents URL appearing in `batchTargetLinks` without headers

**Fix in `HomeView.swift`**:
- Added `&& qualityKind != .direct` to `isYtDlpSite` check — prevents Playmogo being routed to yt-dlp after `mp4=nil` change
